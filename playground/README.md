# Lune Playground — 技術検証 PoC

Pyodide (ブラウザ内 CPython) 上で Lune 処理系を**無改造で**動かす検証。
`documents/STRATEGY.md` の施策 A (ブラウザ Playground) の実現可能性を確認した。

## 動かし方

リポジトリのルートで HTTP サーバーを立て、`/playground/` を開く。

```sh
python3 -m http.server 8642
# → http://localhost:8642/playground/
```

ビルド不要。`index.html` が Pyodide を CDN から読み込み、`/lune/*.py` を
fetch して Pyodide のファイルシステムに書き込み、`check_file` / `eval_file` /
`format_source` / `apply_fixes` / `render_explanation` / `ReplSession` を直接呼ぶ。

## 検証結果 (2026-07-20)

環境: Pyodide v0.26.4 (Python 3.12.1)、ローカル配信、macOS 上のブラウザ。

| 項目 | 結果 |
| --- | --- |
| 処理系の互換性 | **無改造で動作**。全 246 テストが Python 3.12/3.13 でもパス (外部依存は標準ライブラリのみ) |
| 起動時間 | Pyodide 本体 約 4.0 秒 + Lune ソース読み込み 約 0.6 秒 (初回。2回目以降はブラウザキャッシュで短縮) |
| 実行 (`--eval` 相当) | 6 ms — 体感ゼロ |
| 型チェック / 診断表示 | TYP0007 (witness・caret・hint 込み) が CLI と同一の出力 |
| did-you-mean → `fix` | TYP0001 の提案 → 自動修正がエディタに反映 (1 ms) |
| `fmt` | 6 ms で整形 |
| `explain` | 教材解説の全文表示 (1 ms) |

## 分かったこと・注意点

- **実装が Pure Python であることがそのまま武器になる**。WASM 化・移植は不要。
- 診断は ANSI カラーを使わないプレーンテキストなので、行頭パターン
  (`error[` / `warning[` / `= hint:` / `= help:`) の色付けだけで CLI 同等の見た目になる。
- Pyodide 本体のダウンロードは初回 約 10 MB。CDN 依存を避けるなら
  self-host も可能 (静的ファイルのみ)。
- モジュール import (`import` 文を含むプログラム) は 2026-09-08 に対応した。
  当時の見立て「複数ファイルを Pyodide FS に書けば動くはず」はそのとおりで、
  `--module-path` すら要らなかった (下の「複数ファイル」を参照)。

## REPL

右カラムは「出力」と「REPL」のタブになっている。REPL タブは端末の `lune --repl`
と同じ体験を目指したもので、**同じ `lune.repl.ReplSession` をそのまま駆動している**。
`repl_main` は端末専用のフロントエンド (プロンプトループと readline を持つ) なので
使わず、ブラウザ側がその役割を担い、セッション・`SourceMap`・`<repl:N>` の採番だけを
写している。継続行の判定も自前で持たず `lune.repl.wants_more` を呼ぶ (二重実装で
規則がずれるのを避けるため、この関数は private から public に変えた)。

できること:

- 式と宣言。セッションをまたいで束縛が残る (`let a = 10` → `a * 2`)
- `:help` / `:type` / `:thunks` / `:trace` / `:explain` / `:lang` / `:quit` の全コマンド
- 複数行入力。行末が `=` `:` `->` なら `...` プロンプトに入り、空行で確定
- `↑` `↓` で履歴。複数行の入力は 1 行に畳んで呼び戻すので、直して再送できる
- `print` / `println` の出力もトランスクリプトに出る (stdout をリダイレクトしている)
- 診断コードはここでもクリックでき、「出力」タブに切り替わって explain が開く
- **エディタを読み込む** — エディタの宣言をそのままセッションに流し込む。
  プログラムを書いてから REPL で突く、という往復ができる
- **リセット** — セッションとログを捨てて作り直す。履歴だけはシェルと同じ感覚で残す。
  言語セレクタを変えたときも、セッションは作り直される

`:quit` は端末と同じく `bye` を返してセッションを閉じる。閉じたあとは
「リセット」で再開する。

## エディタ(CodeMirror)

エディタは CodeMirror 5(CDN)で、Lune の構文ハイライト(simple mode)・行番号・
Ctrl/Cmd+Enter での実行に対応。CDN が使えない環境では素の textarea に
フォールバックする。診断が `main.lune:行:列` を指すとき、該当行を
エディタ上でハイライトする。

## explain の入口

診断コードの解説を開く道が3つある。

1. **出力や REPL に現れた診断コードをクリックする。** `TYP0007` のようなコードは
   すべてリンクになっていて、押すとその場で解説が開く(選択中の言語で表示)。
2. **コード欄に入れて「explain」を押す。**
3. **コード欄を空のまま「explain」を押す。** いま画面に出ているエラーのコードが
   使われる。見えているほうのペイン(出力 / REPL)を先に見て、そこから拾う。
   どこにも診断が無ければ、勝手にどれかを表示するのではなく使い方を案内する。

3 は以前、**空欄だと無条件に `TYP0007` を表示していた**。`match` を書いたことのない
読者に「網羅的でない match」の解説を出してしまい、初学者を混乱させるので直した。

## 評価する束縛の自動追従

「評価する束縛」の欄は、**エディタの最後のトップレベル束縛に自動で追従する**。
`let answer = twice(21)` を書けば `answer` が入るので、実行前に自分で打ち直す必要はない。

- 判定には**実際のパーサ**(`parse_source`)を使う。正規表現ではないので、文字列の中の
  `let` やコメント、ネストしたブロックの `let` を宣言と間違えない。
- 拾うのは `let` と `var` だけで、`def`(関数)は飛ばす。関数値を表示したい場面は
  ほぼないため。
- 書きかけでパースできない間は、直前の値をそのまま保つ。
- **欄を手で編集したら、以後は上書きしない。** ユーザーが選んだ値のほうが強い。
  「新規」やサンプルの切り替えで追従が復活する。
- 空のエディタでは `main` が入る。慣例の当たりを付けるためで、束縛を1つ書けば
  そちらに置き換わる。

## 新規・開く・保存

「新規」でエディタを空にして書き始められる。サンプルの選択も「(なし)」に戻り、
評価する束縛の欄も空になる。エディタに何か入っているときだけ確認を挟む
(バッファは1つしかないので、新規作成はその内容を捨てることになる)。
`Ctrl/Cmd+N` はブラウザの「新しいウィンドウ」に取られていて横取りできないため、
これはボタン専用にしてある。

サンプルのセレクタは「いまエディタに何が入っているか」を表すので、共有リンクで
開いたときやファイルを読み込んだとき、新規作成したときは「(なし)」になる。

## ローカルファイルの読み書き

「開く」(`Ctrl/Cmd+O`)と「保存」(`Ctrl/Cmd+S`)で、ローカルの `.lune` ファイルを
エディタに読み込み、また書き出せる。どちらもブラウザ内で完結し、サーバーには
何も送らない。両者は同じ構造で、対応するブラウザではネイティブのダイアログを使い、
そうでなければ従来の方法にフォールバックする。

| | 対応ブラウザ (Chromium 系) | フォールバック |
| --- | --- | --- |
| 開く | `showOpenFilePicker` | `<input type="file">` |
| 保存 | `showSaveFilePicker` (保存先と名前を選べる) | `main.lune` としてダウンロード |

どちらもキャンセルは失敗と区別して扱う。読み込みをキャンセルしても、エディタの
内容はそのまま残る。API 名だけあって権限が下りない場合はフォールバック経路に落ちるので、
書きかけのコードを失うことはない。

「開く」はエディタの内容を**置き換え**、前の診断の行ハイライトを消す。

### ドラッグ&ドロップ

エディタにファイルをドロップしても読み込める。これは CodeMirror 5 が元から
持っている機能で、「開く」と違い**ドロップした位置に挿入**する(置き換えではない)。

### 保存するときの末尾改行

保存する内容には**末尾改行を補う**。付けないと、書き出したファイルが
`lune fmt --check` で `would reformat` になる(ユーザーが打っていない理由で
CI が落ちてしまう)。

ダウンロード時の既定名を `main.lune` にしているのは、診断が `main.lune:行:列` と
表示するのと揃えるため。

## 複数ファイル(`import`)

エディタの上にファイルタブがある。`main.lune` が入口で、「＋ モジュール」で
`import` に書く名前(`math`、`util.text` のようなドット区切りも可)を与えると
タブが増える。実行と型チェックは**常にプログラム全体**を対象にする —
モジュールのタブを開いていても、評価されるのは `main.lune` である。

処理系側の変更は要らなかった。モジュール解決は入口ファイルのあるディレクトリを
探索する(`module_loader._search_roots`)ので、`/app` に並べて書き出すだけで
`import geometry` が `/app/geometry.lune` に解決される。ドット区切りの名前も
ディスク上と同じく `util.text` → `util/text.lune` になる。

注意点が3つある。

- **タブを消したらファイルも消す。** 消し忘れると、そのモジュールが Playground
  でだけ import できる状態になり、手元に持ち帰ると動かないプログラムができる。
  駆動側は前回書いたファイルを覚えていて、消えたものを毎回削除する。
- **エラーの行ハイライトは、画面に出ているファイルのものだけ。** 別ファイルの
  エラー行を、たまたま開いているファイルに塗ると無関係なコードを指してしまう。
- **REPL は `import` を解決しない。** `import math` に `ok` と答えるが名前は入らない
  (処理系側の制限)。「エディタを読み込む」でその旨を出すようにしてある。

サンプル「import で分ける(2ファイル)」がこの機能のデモで、
`tests/test_playground_driver.py` が**実際に動くプログラムであることを検査**している。

## 共有リンク

「共有」ボタンで、コード・評価する束縛・トレース設定・言語を URL の
`#s=`(base64url の JSON)に畳み込んでクリップボードにコピーする。
開いた側はページ読み込み時にそのまま復元される。演習の配布に使える。
モジュールがあるときだけ `m`(名前とコードの配列)が加わるので、
単一ファイルのリンク(教科書やチュートリアルが生成するもの)は以前のまま短い。

## 診断カタログページ

`errors.html` は `documents/ERROR_INDEX_JA.md` / `ERROR_INDEX.md` をその場で
レンダリングする静的ページ(日英切り替え付き)。Rust の error index に相当する。

## GitHub Pages

`.github/workflows/pages.yml` が main への push でリポジトリ全体を GitHub Pages
にデプロイする。ランディングページ(リポジトリルートの `index.html`)、
Playground、診断カタログが公開される。ページ内の fetch はすべて相対パスなので、
プロジェクトページのサブパス配信 (`/<repo>/...`) でもローカル配信でも動く。

## explain の言語切り替え

explain ボタンの隣のセレクタで、診断詳解を**日本語/英語**で切り替えられる
(`lune explain <CODE> --lang ja` と同じ内容。カタログは `lune/explanations_ja.py`)。

## トレース(遅延評価の観察)

「トレース」チェックボックスを有効にして実行すると、評価器の trace hook
(`set_trace_hook`)経由で **いつ・どの thunk が force されたか** が入れ子の
深さ付きで表示される(`REPL_SPEC.md` §5.2 と同じイベント)。プリセット
「無限ストリーム(トレースで観察)」が需要駆動の評価を見るデモになっている。
