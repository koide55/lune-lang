## 2. 対象読者と前提

- 何か1つの言語（Python など）で簡単なプログラムを書いた経験がある人。
- **関数型プログラミングは未経験でよい**。ADT・パターンマッチ・遅延評価は本書で初めて学ぶ前提。
- 日本語話者。エラーメッセージの読み方を母語で教えることを本書の柱にする（STRATEGY.md 施策 B/C と整合）。
- 想定読了: 通読で数日〜数週間。第II部以降は独立性を持たせ、リファレンス的な拾い読みにも耐える構成にする。

## 3. 本書の設計方針（K&R から借りるもの / Lune 固有のもの）

K&R から借りる骨格:

1. **最初に全体を1周する章**（K&R 第1章「やさしい入門」方式）。文法の完全性より「動くプログラムを書いて動かす体験」を優先。
2. **例中心**。すべての概念は動くコード例で導入し、説明は例の後に置く。
3. **各節に演習問題**。難易度を ★（写経+改変）/ ★★（小さな設計）/ ★★★（章をまたぐ統合）の3段階で明示。
4. **巻末リファレンスマニュアル**（K&R 付録A方式）。本文は読み物、付録は規範的な文法・ライブラリ・診断の一覧。

Lune 固有の柱（他言語の教科書にない要素）:

5. **エラー駆動学習**: 各章に「壊してみよう」ボックスを置く。わざとエラーを起こす → 診断を読む → `lune explain` → 直す（可能なら `lune fix`）のループを、章の題材で毎回回す。TUTORIAL.md 第17章「エラーを読む、エラーから学ぶ」の手法を全章に分散させる。
6. **遅延評価を「観察」しながら教える**: `:thunks` / `:trace` を第4章以降の常用ツールにする。「遅延は初学者の罠」という一般論に対し、可観測化で答えるという設計判断（STRATEGY.md 施策 E）を本の構成そのもので体現する。
7. **REPL ファースト**: 例は原則 REPL トランスクリプト（`lune>` プロンプト）で示し、まとまったプログラムのみファイル+`--check`/`--eval` で示す。

各章の標準構成:

- 導入例（動くコード）→ 概念の説明 → 発展例
- 「壊してみよう」ボックス（その章で出会う診断コードを1〜3個）
- 「観察してみよう」ボックス（遅延に関わる章のみ。`:thunks` / `:trace`）
- まとめ（構文とライブラリの一覧表）
- 演習問題（解答は各問題の直下に折りたたみで置く。§7 参照）
- 「より正確には」: 対応する仕様書（`documents/*_SPEC.md`）への参照

### 序章 Lune へようこそ（〜8ページ）

- Lune とは何か: **Lazy and Native** — デフォルト遅延（Lazy）と、母語で教える診断（Native language）。
- 設計思想「コンパイラが教える」: エラーは失敗の通知ではなく教材である、という本書全体の態度表明。
- 本書の読み方: REPL を開きながら読む。エラーが出たら成功。「壊してみよう」の使い方。
- 実行環境: `./bin/lune`（REPL / ファイル実行）、ブラウザ Playground。動作確認の手順。
- 表記法: REPL トランスクリプト、診断表示の読み方の予告。

### 第1章 やさしい入門（〜20ページ）— K&R 第1章方式

ゴール: **30分で「書いて、動かして、エラーを読んで直す」を1周する。**

- 1.1 REPL を起動する。数と文字列。`show`。
- 1.2 `let` で名前を付ける（遅延には触れず「値に名前を付ける」とだけ言う。伏線として「実は評価はまだ起きていない」を1行だけ予告）。
- 1.3 最初のプログラムをファイルに書く: `module` 宣言、`def`、`IO:` ブロックと `println`（hello, world）。`--eval` で動かす。
- 1.4 `if` は式である。
- 1.5 リストと `map` / `filter` / `fold` の最初の一歩。
- 1.6 **最初のエラー**: わざと変数名を打ち間違える → `TYP0001` と did-you-mean を読む → `lune explain TYP0001` → `lune fix` で直る体験。
- 1.7 この本の残りで学ぶことの地図。
- 演習: 温度換算表（K&R 1章オマージュ）、fold で合計・最大値、エラーを1つ起こして explain を読む。

- 2.2 算術・比較・論理演算子。0除算が**診断付き実行時エラー**（RUN 系）になること。

- 2.4 `let ... in` 式。
- 2.5 型注釈の書き方と、書かなくてよい場所（局所型推論の予告。詳細は第3章・付録A）。
- 2.6 タプル `(a, b)` と `Tuple[Int, String]`。
- 壊してみよう: `LXL0001`（不正な文字）、`LAY0001`（インデント不一致）、型不一致 `TYP0003`。

### 第3章 関数（〜18ページ）

- 3.1 `def` による定義。引数と戻り値の型注釈。
- 3.2 関数は値: 関数型 `Int -> Int`、変数への束縛。
- 3.3 ラムダ `fn x -> x + 1`。期待型伝播でパラメータ型が省ける場面・省けない場面（`TYP0010` 警告）。
- 3.4 高階関数: 関数を取る関数、返す関数。
- 3.5 **部分適用**: `add(1)` が関数になる。カリー化との関係。
- 3.6 パイプライン `|>`: `x |> f |> g` の読み方。「データの流れ」として関数合成を導入。
- 3.7 再帰。再帰関数には戻り値型が要る（`TYP0011`）。
- 壊してみよう: 引数の数間違い `TYP0005`、呼べない値を呼ぶ `TYP0004`、`TYP0011`。
- 演習: パイプラインへの書き換え、部分適用によるユーティリティづくり、再帰で階乗・フィボナッチ（第8章のストリーム版への伏線）。

### 第4章 遅延評価 — Lune の心臓部（〜24ページ）★本書の看板章

「遅延は隠すのではなく観察して学ぶ」を体現する章。K&R にはない、Lune 教科書の独自性の中心。

- 4.1 `let` は約束である: 束縛しただけでは評価されない。失敗する式を束縛しても、使うまでエラーにならない実演。
- 4.2 サンクという考え方: 未評価 / 評価済み / 失敗（の記憶）の3状態。
- 4.3 **観察する**: REPL `:thunks` で束縛の状態を見る。`:trace`（CLI `--trace`）で「いつ・何が force されたか」をソース位置付きで見る。以降の章でもこの2つを使い続けることを宣言。
- 4.4 関数引数も遅延される: 使わない引数は評価されない。自作 `myIf` が書ける、という遅延の威力。
- 4.5 メモ化: 2回使っても1回しか評価されない。失敗もメモ化される。
- 4.6 正格化の道具箱: `strict let` / 正格引数 / `lazy` と `force` / `seq` / `deepForce`。「デフォルト遅延 + 明示的オプトアウト」という設計の全体像。
- 4.7 再帰サンク: `let x = x + 1` が無限ループせず `RUN0005` で検出される仕組み（ThunkState）。GHC の `<<loop>>` との比較コラム。
- 4.8 いつ遅延が効くか / いつ正格にすべきか: 指針とアンチパターン。
- 壊してみよう: `RUN0005` を explain まで読む。失敗メモ化を `:thunks` で確認する。
- 出典: `LAZY_EVALUATION_SPEC.md` / `REPL_SPEC.md` §5.1。

### 第5章 代数的データ型とパターンマッチ（〜20ページ）

- 5.1 「形」を型にする: `type Shape: | Circle(Double) | Rect(Double, Double)`。
- 5.2 `match` 式: コンストラクタパターン、リテラル、ワイルドカード、タプルパターン、ガード。
- 5.3 **網羅性検査と反例（witness）**: ケースを1つ消すと `TYP0007` が「足りないパターンの実例」を教えてくれる。この診断を「仕様の抜けを見つける道具」として位置づける。
- 5.4 到達不能なケース `TYP0009`、`let`/`for` に置けない反駁可能パターン `TYP0008`。
- 5.5 ジェネリックな ADT: `Option[T]` と `Result[T, E]` を自分で作ってみる → 実は prelude にある、へ接続。
- 5.6 Option / Result の実践: `getOrElse`、`optionMap`、`unwrapOr`、`resultMap`。「例外の代わりに値で失敗を表す」。
- 壊してみよう: `TYP0007`（witness を読む）→ ケース追加 → 今度は `TYP0009` を出す、の往復。
- 出典: `MATCH_EXHAUSTIVENESS_SPEC.md` / `LANGUAGE_SPEC.md` §10–11。

### 第6章 レコード（〜12ページ）

- 6.1 `record User: name: String / age: Int`。名前付き構築 `User(name = "Ada", age = 36)`。
- 6.2 フィールドアクセス。フィールドも遅延される（`:thunks` で観察）。`strict` フィールド。
- 6.3 ジェネリックなレコード。
- 6.4 ADT とレコードの使い分け指針（直和は type、直積に名前が欲しければ record）。
- 6.5 現状の制限: record update / record pattern は未対応（付録Eへ参照）。
- 壊してみよう: `REC0002`（未知フィールド + did-you-mean）、`REC0003`（不足）、`REC0006`（名前なし構築）。
- 出典: `RECORD_FIELD_SPEC.md`。

### 第7章 null 安全（〜16ページ）

- 7.1 `T?` — null を型で管理する。`Int?` に `42` も `null` も入る。
- 7.2 `match` で外す: `null` ケースを書くと残りが `Int` に絞り込まれる（narrowing）。網羅性検査が `null` の考慮漏れを防ぐ。
- 7.3 `??` でデフォルト値（短絡評価であることを `:trace` で観察）。
- 7.4 `?.` 安全ナビゲーション。
- 7.5 `if x != null` による flow narrowing。
- 7.6 `Option[T]` と `T?` の使い分け: 二重の「なし」（`Some(null)` に相当するもの）を表せるか、という観点で整理。
- 壊してみよう: `T?` を裸の `T` として使って `TYP0003`、`match` の `null` ケース漏れで `TYP0007`。
- 出典: `LANGUAGE_SPEC.md`（null 安全の節）/ `samples/nullable.lune`。

### 第8章 リストとストリーム（〜22ページ）★遅延の応用編

第4章で学んだ遅延が「データ構造の設計」に化ける章。Haskell 系教科書の魅力ポイントを、観察ツール付きで。

- 8.1 リストの正体: `Cons` / `Nil`。リテラル `[1, 2, 3]`。`Cons` の tail は遅延フィールド。
- 8.2 基本操作: `head` / `tail`（Option を返す設計に注目）、`length`、`map` / `filter` / `fold`、`take` / `drop`、`range`、`isEmpty`。
- 8.3 **リストは無限になれる**: 専用の Stream 型がないことの意味。`naturalsFrom` / `iterate` / `repeat` / `cycle`。
- 8.4 遅延コンビネータ: `takeWhile` / `dropWhile` / `zip` / `zipWith`。無限リスト同士を zip する。
- 8.5 停止しない操作: `fold` / `length` / `drop` を無限リストに使うとどうなるか（実演と、`:trace` での観察）。
- 8.6 実例集: フィボナッチ（zipWith 版）、エラトステネスの篩、移動平均、`cycle` での周期パターン。
- 壊してみよう: 無限リストの `length`（止まらないことを体験して Ctrl-C）、`take` の引数順ミスで型エラー。
- 出典: `STANDARD_LIBRARY_SPEC.md` §6 / `samples/stream.lune`。

### 第9章 命令的に書く — var・while・for・IO（〜14ページ）

- 9.1 「式で考える」が基本、でも小さなループは命令的に書いてよい、という Lune の現実主義。
- 9.2 `var` と再代入。`let` との違い（var は正格か遅延か、仕様に沿って正確に）。
- 9.3 `while`。

- 9.6 `raise` / `throw` と実行時エラー（try/catch はまだ無い → Result を使う、第5章参照）。
- 壊してみよう: `TYP0006`、IO の外で println を呼ぶとどうなるか。
- 出典: `WHILE_LOOP_SPEC.md` / `FOR_LOOP_SPEC.md` / `LANGUAGE_SPEC.md` §9.6–9.8。
