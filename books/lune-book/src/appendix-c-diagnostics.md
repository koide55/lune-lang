# 付録C 診断コード一覧

Lune のコンパイラと評価器が発行する診断コードの全一覧です。本書はここで「地図」に徹します
——各コードの詳しい解説（何が起きたか / 再現する最小の例 / 直し方）は本書に写さず、
`lune explain CODE`（REPL では `:explain CODE`）に委ねます。同じ内容は
[診断カタログ](https://koide55.github.io/lune-lang/playground/errors.html) と
`documents/ERROR_INDEX_JA.md`（英語版は `ERROR_INDEX.md`）でも読めます。

```console
$ lune explain TYP0007          # 1つのコードを読む
$ lune explain --index          # 全コードの詳解を一覧する
```

コードの頭3文字は**族**で、そのままコンパイラの検査段階に対応します。族の意味と読み方は
第11章 11.2 節にあります。

「解説のないコードに出会う」ことは起きません。`tests/test_explanations.py` の
`test_every_emitted_code_has_an_explanation` が、コンパイラが発行しうる全コードに詳解が
あることを検査しており、詳解を書かずにコードを増やすとテストが落ちるようになっています。

## 表の読み方

- **本文で触れている章** — そのコードが本文に登場する章です。第11章は診断のしくみそのものを
  扱う章なので、ほとんどのコードに触れています。
- **動く例** — `books/examples/` にそのコードを実際に再現する検証済みの例がある章です。
  「自分で出してみたい」ときの入口として使ってください。`—` は、本書に狙って出す例を
  置いていないコードです（`LAY0002` や `REC0001` のように、意図的に出すにはひと工夫要るもの）。
- 警告（`warning`）として出るものは意味の欄に「（警告）」と書いてあります。警告は
  `--check` を失敗させません。

## 番号の飛びについて

番号が連番になっていないことに気づいたかもしれません。`TYP0002` と `RUN0001`〜`RUN0004`
が欠けています。

`RUN` 系は、設計段階では実行時エラーを種類ごとに分ける予定でした（`RUN0004` は
「実行時の非網羅 match」用に用意されていました）。実装ではその方針をやめ、再帰サンクの
force だけを専用の `RUN0005` に残して、残りは汎用の `RUN0006` に集約しています。
未定義変数も、失敗したサンクの force も、標準ライブラリの型不一致も、実行時の非網羅
match も、みな `RUN0006` です。`TYP0002` は単なる欠番です。詳しくは
`documents/ERROR_DIAGNOSTICS_SPEC.md` を参照してください。

**欠番を埋め直すことはしません。** 一度公開した番号が後から別の意味になるほうが、
飛びがあるより読者にとって害が大きいからです。エラー番号は調べるための鍵であって、
通し番号ではありません。

## この付録の出どころ

この表の「コード」「分類」「意味」は `documents/ERROR_INDEX_JA.md` から作っています。
その索引自体も手書きではなく、コンパイラのカタログから生成されたものです。

```console
$ ./bin/lune explain --index --lang ja > documents/ERROR_INDEX_JA.md
```

つまりこの表の出どころは `lune/explanations_ja.py` のカタログであり、コンパイラの実装と
同じ一次情報です。コードを追加・変更したときは、索引を作り直してからこの表を更新してください。
