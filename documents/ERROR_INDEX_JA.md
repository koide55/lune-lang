## LAY0001

**インデントが揃っていない**

Lune は Python と同じく、インデント（レイアウト）でブロックを区切ります。
ある行のインデントがどの外側ブロックとも揃っていないため、コンパイラは
ブロックの始まりと終わりを判断できませんでした。

発生する例:

```lune
def f(x: Int): Int =
    let y = x
      y + 1        # 深すぎる: 上のブロックと揃っていない
```

直し方:

継続行はブロックの下に一貫したインデントで置いてください。同じ深さの行には
同じ数のスペースを使い、幅の違うインデントを混ぜないでください。

## LAY0002

**対応しない閉じ括弧**

対応する開き括弧のない `)`、`]`、`}` が見つかりました。

発生する例:

```lune
let x = (1 + 2))   # `)` が 1 つ多い
```

直し方:

余分な括弧を削除するか、閉じるはずだった開き括弧を追加してください。

## LXL0001

**予期しない文字**

字句解析器が、どの Lune トークンにも属さない文字に出会いました。

発生する例:

```lune
let x = $1         # `$` はここでは使えない文字
```

直し方:

その文字を削除するか、正しい文字に置き換えてください。

## LXL0002

**文字列・文字リテラルが閉じていない**

文字列 `"..."` または文字 `'.'` リテラルが行内で閉じられていないか、
文字リテラルの中身がちょうど 1 文字ではありませんでした。

発生する例:

```lune
let s = "hello     # 閉じる引用符がない
let c = 'ab'       # 文字リテラルはちょうど 1 文字
```

直し方:

引用符を閉じてください。文字列は `"..."`、1 文字は `'x'` と書きます。

## LXL0003

**ブロックコメントが閉じていない**

`###` ブロックコメントが開かれたまま、閉じられていません。

発生する例:

```lune
### このコメントは終わらない
let x = 1
```

直し方:

閉じ側の `###` を追加してください。

## LXL0004

**インデントにタブは使えない**

Lune のインデントはスペースで書きます。行頭にタブ文字があると、レイアウトの
解釈が曖昧になるため許可されていません。

直し方:

行頭のタブをスペースに置き換えてください（エディタをスペース挿入に設定するのがおすすめです）。

## MOD0001

**モジュールが見つからない・読めない**

`import` をモジュール検索パス上の `.lune` ファイルに解決できなかったか、
ファイルはあるものの読み取れませんでした。

発生する例:

```lune
import math        # 検索パスに math.lune が見つからない
```

直し方:

モジュール名とファイルパスを確認してください。検索ルートは `--module-path PATH` で追加できます。

## MOD0002

**モジュールの循環 import**

2 つ以上のモジュールが互いを import して循環しています。Lune はモジュールを
依存順に読み込むため、循環があると順序を決められません。

直し方:

循環を断ち切ってください。共有する定義を第 3 のモジュールに移し、両方からそれを import するのが定石です。

## MOD0003

**module 宣言の不一致**

ファイルの `module X` 宣言が、import されたときのパスと一致していません。

直し方:

`module` 宣言を import パスに合わせて直すか、宣言されている名前で import してください。

## PRS0001

**予期しないトークン**

構文解析器が、読んでいる構文の開始にも継続にもなり得ないトークンに
出会いました。

直し方:

キャレット周辺の構文を確認してください。キーワード・演算子・区切り記号が欠けているか、置き場所が違う可能性が高いです。

## PRS0002

**特定のトークンが必要**

構文解析器は特定のトークン（NEWLINE や `)` など）を必要としましたが、別の
ものが見つかりました。よくある原因は、`type` 宣言を 1 行に書いてしまうこと
です。

発生する例:

```lune
type Color = | Red | Green | Blue      # 1 行には書けない

type Color =                           # コンストラクタはインデントした行に
    | Red
    | Green
    | Blue
```

直し方:

メッセージが示す形に合わせて、足りないトークンを補うか、複数行に分けてください。

## REC0001

**レコードフィールドの重複宣言**

`record` 宣言の中で、同じフィールド名が複数回使われています。

発生する例:

```lune
record User:
    name: String
    name: Int      # 二重に宣言されている
```

直し方:

重複したフィールドの名前を変えるか、削除してください。

## REC0002

**存在しないレコードフィールド**

そのレコード型が宣言していないフィールドにアクセスしました。

発生する例:

```lune
record User:
    name: String
let u = User(name = "Ada")
let a = u.age      # User に `age` というフィールドはない
```

直し方:

宣言されているフィールドにアクセスしてください。綴りも確認してください。

## REC0003

**レコードフィールドの不足**

宣言されているフィールドをすべて与えずにレコードが構築されました。

発生する例:

```lune
record User:
    name: String
    age: Int
let u = User(name = "Ada")   # age がない
```

直し方:

レコードを構築するときは、宣言されている全フィールドを与えてください。

## REC0004

**初期化でフィールドを二重指定**

レコードの構築で、同じフィールドが複数回設定されました。

発生する例:

```lune
User(name = "Ada", name = "Bob")   # name を 2 回設定
```

直し方:

各フィールドはちょうど 1 回だけ設定してください。

## REC0005

**宣言されていないフィールドの指定**

レコードの構築で、そのレコード型が宣言していないフィールドが設定されました。

発生する例:

```lune
record User:
    name: String
User(name = "Ada", age = 36)   # User に `age` というフィールドはない
```

直し方:

レコードが宣言しているフィールドだけを設定してください。

## REC0006

**レコードは名前付きで構築する**

レコードは名前付きフィールド（`フィールド = 値`）で構築します。位置引数では
構築できません。

発生する例:

```lune
record User:
    name: String
User("Ada")        # User(name = "Ada") と書く必要がある
```

直し方:

各フィールドを `フィールド = 値` の形で指定して構築してください。

## RUN0005

**再帰的なサンク評価**

遅延値の定義がその値自身を必要としているため、いつまで待っても計算が
完了しません。

Lune は束縛を遅延評価します。各 `let` はサンク（thunk）を作り、最初に
force されたときに一度だけ計算されます。計算を始める前にサンクは
「評価中」の印を付けられます。計算が巡り巡って同じサンクを再び force
したら、その定義は自己参照であり、どれだけ待っても値は得られません。
そこで Lune は永久に走り続ける代わりに、このエラーを即座に報告します。

再帰「関数」は問題ありません。`def` の本体は呼ばれたときにだけ実行される
ので、`fact(n - 1)` のような呼び出しが関数自身の定義を force することは
ないからです。存在できないのは再帰「値」です。

発生する例:

```lune
let x = x + 1      # x の値が x 自身を必要としている

let a = b
let b = a          # どちらを force しても自分に戻ってくる
```

直し方:

再帰は関数として書いて（`def f(n: Int): Int = ... f(...) ...`）呼び出すか、
どの値も自分自身の結果に依存しないように束縛を組み替えてください。

## RUN0006

**実行時エラー**

実行時に評価が失敗しました。よくある原因: 未定義変数の使用、ゼロ除算
（`/` / `//` / `%`）、以前に失敗したサンクの force、標準ライブラリに渡した
値の形の誤り、実行時にどのケースにもマッチしなかった `match` など。
型の合わない被演算子への演算子適用（`"a" - 1`、`if 1 then ...`）もここで
報告されます。これは型検査を飛ばす `lune --eval` でのみ起こります。

直し方:

具体的な原因はメッセージを読んでください。実行時エラーの多くは `lune --check` が先に見つけてくれるので、まずファイルを型チェックするのがおすすめです。

## TYP0001

**未定義の名前**

現在のスコープで束縛されておらず、prelude にも import にも見つからない
名前が使われました。

発生する例:

```lune
let y = x + 1      # x はどこにも定義されていない
```

直し方:

使う前に名前を定義または import してください。綴りも確認してください。

## TYP0003

**型の不一致**

式の型が、文脈の要求する型と一致しません。文脈とは `let` や引数の型注釈、
関数の引数、`if`/`match` の分岐、演算子、戻り値型などです。

発生する例:

```lune
let x: Int = "hi"  # Int が必要なのに String
```

直し方:

値の型を期待される型に合わせるか、型注釈のほうを変えてください。

## TYP0004

**呼び出せない値**

関数でもデータコンストラクタでもない値に、引数が渡されました。

発生する例:

```lune
let x = 1
let y = x(2)       # x は Int であって関数ではない
```

直し方:

呼び出せるのは関数・ラムダ・コンストラクタだけです。

## TYP0005

**引数の個数が違う**

関数またはコンストラクタに引数が多すぎるか、部分適用できないものに対して
少なすぎます。

発生する例:

```lune
def add(x: Int, y: Int): Int = x + y
let z = add(1, 2, 3)   # add の引数は 2 つ
```

直し方:

正しい個数の引数を渡してください。ユーザー定義関数に少なく渡した場合は部分適用になります。

## TYP0006

**for の対象は List でなければならない**

`for` ループが走査できるのは `List[T]` だけです。

発生する例:

```lune
for x in 10:       # 10 は Int であって List ではない
    print(x)
```

直し方:

`List[T]` を走査してください。例: `range(0, 10)`。

## TYP0007

**網羅的でない match**

`match` が、対象の取りうる値をすべてカバーしていません。メッセージには
witness（反例）— どのケースにも当たらない値の実例 — が表示されます。
nullable な `T?` では、`null` と中身の値の両方をカバーする必要があります。

発生する例:

```lune
type Color =
    | Red
    | Green
    | Blue

def name(c: Color): Int =
    match c:
        | Red -> 1
        | Green -> 2     # Blue がカバーされていない
```

直し方:

漏れているパターンのケースを追加するか、ワイルドカードケース `| _ -> ...` を追加してください。

## TYP0008

**束縛に反駁可能パターンは使えない**

`let` と `for` の束縛は irrefutable（必ずマッチする形）でなければ
なりません。失敗し得るパターン（コンストラクタ、リテラル、`null`）は
そこには書けません。

発生する例:

```lune
let Some(x) = findUser()   # None だとマッチに失敗し得る
```

直し方:

`match` で場合分けするか、ただの名前か `_` で束縛してください。

## TYP0009

**到達しない match ケース（警告）**

先行するケースがすでに全ての値をカバーしているため、決してマッチしない
ケースがあります。これはエラーではなく警告です。

発生する例:

```lune
match c:
    | _ -> 0
    | Red -> 1     # 到達しない: 上のワイルドカードが先にマッチする
```

直し方:

冗長なケースを削除するか、それをカバーしているケースより前に移動してください。

## TYP0010

**引数の型を推論できない（警告）**

ラムダの引数の型を文脈から推論できず、`Any` にフォールバックしました。
その引数については型チェックが弱くなります。

発生する例:

```lune
let f = fn x -> x + 1      # x の型を推論する文脈がない
```

直し方:

引数に注釈を付ける（`fn x: Int -> ...`）か、期待される型が分かる場所（`map` の引数など）でラムダを使ってください。

## TYP0011

**再帰関数には戻り値型が必要**

自分自身を呼ぶ関数には、明示的な戻り値型の注釈が必要です。再帰呼び出しを
チェックする時点では、その関数の型がまだ確定していないためです。

発生する例:

```lune
def fact(n: Int) =                 # 戻り値型がない
    if n <= 1 then 1 else n * fact(n - 1)
```

直し方:

戻り値型の注釈を追加してください。例: `def fact(n: Int): Int = ...`。

## TYP0012

**ここでは名前付き引数を使えない**

フィールド名を指定して構築できるのはレコードだけです。関数と ADT のコンストラクタ
は引数を位置で受け取り、部分適用もできるため、`名前 =` というラベルには対応させる
先がありません。そのため、黙って無視せずエラーにします。

この検査が入る前はラベルが黙って捨てられていたため、同じ型の引数どうしが診断なしで
入れ替わることがありました。

発生する例:

```lune
type Point =
    | P(x: Int, y: Int)

let p = P(y = 1, x = 2)     # この検査が入る前は x = 1, y = 2 と黙って束縛されていた
```

直し方:

宣言順に位置引数で渡してください: `P(2, 1)`。フィールド名で構築したい場合は `record` を使ってください。
